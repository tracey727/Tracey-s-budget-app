Covers every new engine module (`src/lib/engine/{waste,capacity,
recurringCost,patterns,savings,alerts}.ts`) plus the pre-existing bills/
forecast/payday/status/safeToSpend suite:

- **State transitions**: `canAdvanceWasteStatus`, `canAdvanceSavingsState` —
  forward-only, one step at a time, each gate's required field enforced
  (baseline before intervention, post-value before measuring, evidence +
  verifier before verifying).
- **Deadline/renewal calculations**: `isRenewalApproaching`.
- **Savings calculations**: `computeVerifiedAmount` per category (recovered
  revenue vs avoided cost vs released time), `annualisedSaving`,
  `summariseSavings` reconstructing dashboard totals purely from case rows.
- **Double-counting prevention**: `isDuplicateSourceLink` /
  `isAlreadyLinked`, mirrored by the `SavingsCase` table's
  `@@unique([sourceType, sourceId])` constraint (see migration
  `0002_practice_savings_phases_12_22`) — the rule is enforced at both the
  application layer (testable without a DB) and the database layer
  (defence in depth).
- **Permission predicates**: n/a — this build has no role system (see
  `00_SCOPE_NOTE.md`); what's tested instead is workflow-gate predicates
  (`canAdvanceSavingsState` requiring an `approvedBy`/`verifiedBy` name).

### Tenant-isolation code audit (manual, documented — not an automated test)
Every new Prisma call in `src/app/(app)/practice/**` and
`src/app/(app)/subscriptions/actions.ts` was read end-to-end and confirmed
to filter by `userId: session.user.id` — either directly in the query, or
via an ownership-checked `findFirst({ where: { id, userId } })` immediately
before any `update`/`create` that only addresses by `id`. No query reads or
writes another user's row. This matches the isolation pattern already used
by every pre-existing model (`Bill`, `Account`, `Transaction`, etc.) — see
`00_SCOPE_NOTE.md` for why this is per-`User` rather than per-organisation.

### Migration review (static, not applied)
`prisma/migrations/0002_practice_savings_phases_12_22/migration.sql` was
generated by `prisma migrate diff` directly from the schema files (additive
only: new enums, new tables, new nullable/defaulted columns on

statement (no `DROP`, no `NOT NULL` added to an existing column without a
default) — a fresh database can apply `0001_init` then `0002_...` in order,
and an existing production database can apply `0002_...` alone without
touching existing rows.

## UAT script (for whoever pilots this — synthetic data only)

1. **Waste**: log a recurring waste event, confirm root cause, plan and
   start an intervention, record a measurement, send it to the ledger,
   approve → implement → measure → verify it. Confirm the waste event's own
   status flips to Verified and the dashboard's "released staff minutes"
   figure updates.
2. **Capacity**: record two consecutive capacity snapshots with some
   approved leave and some waiting demand; confirm the dashboard shows a
   trend and never counts leave as avoidable.
3. **Recurring cost**: add a subscription, set a renewal date within 30
   days, confirm the "review before renewal" flag appears; record a
   cost-reduction decision and confirm a savings case appears in the
   ledger with the pre/post amounts.
4. **Patterns**: identify a pattern, link the waste event from step 1 to
   it, assign a prevention action with an owner/due date, start it, and
   record a measured result.
5. **Alerts**: create one rule per trigger type, run the check, confirm
   each fires at most once per open condition, acknowledge one and mark
   another actioned, re-run the check and confirm the actioned one's
   condition can re-alert if it recurs but the acknowledged-but-still-open
   one does not duplicate.
6. **Dashboard**: confirm every headline figure matches what you'd get by
   manually summing the underlying list pages.

**Acceptance rule carried over from the blueprint**: a phase cannot be
marked GREEN if the pilot user has to rely on memory or an external note to
complete a workflow the system claims to control. Everything above should
be completable from in-app queues/forms alone.
